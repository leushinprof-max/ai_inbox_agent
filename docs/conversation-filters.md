# Conversation filters

**First reply** filters by the earliest incoming message's provider timestamp across the entire stored conversation history, before pagination. Later replies and our outgoing messages do not change this date. Because the date is computed from stored messages at query time, incoming messages imported later with older timestamps count automatically. Available periods: Today, This week (Monday onward), This month, and Custom dates (both dates inclusive). The list uses the current workspace timezone, including when opening saved views. Saved views may also use Last 7, 30 or 90 days; the period menu offers only the four periods above. Custom dates uses an inline calendar with month navigation, a highlighted range and keyboard arrow navigation, in its own full-width row. Conditions can be combined with Intent → Positive or any label, and saved as pinned views. With First reply applied, the list shows an exact matching lead/conversation total across all pages. Each conversation is counted once; the same person in separate conversations is counted separately. The result depends on the history available from the provider/import.

`conversation_page_v3` evaluates First reply. `conversation_count_v3` uses the same predicates, runs as security invoker and returns the exact total. The partial index `messages_first_reply_idx` on incoming messages supports the lookup.

The filter builder supports labels (any / none), intent (positive / neutral / negative, is / is not), last activity (within / older than 24 hours, 7, 30 or 90 days), last message direction (contact / our team), and read status. Intent comes from the assigned label's group in the workspace catalog; unlabeled conversations never match "Intent is" and always match "Intent is not". Filter fields are fixed after adding a row; remove the row to choose a different field. A filter holds up to 10 conditions. Conditions use AND; selected labels within one condition use OR. Changes remain a draft until **Apply filters** or **Save view**. Closing the panel discards unapplied changes. **Clear all** clears the draft conditions; apply to reset the results.

**Pin view** saves a named set of conditions in browser storage, scoped to user and workspace. It does not save the search text. There are no predefined views. The view strip, including the **All** reset button, only appears when at least one view is pinned. Removing the final pin hides the strip. Removing the active view also resets its conditions. Saved views persist across reloads in that browser; they do not sync between devices.

Lists without filter conditions, including search-only lists, use `conversation_page_v2`; any condition switches to the read-only, security-invoker `conversation_page_v3` RPC. All conditions are applied before the keyset cursor and page limit. Workspace authorization and table RLS still apply.

Focused tests are in `tests/conversation-filters.test.ts`, `tests/integration/conversation-filters.test.mts` and `tests/integration/conversation-cache.test.mts`.
